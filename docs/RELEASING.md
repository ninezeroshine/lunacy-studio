# Как выпустить новую версию

Пользователи получают обновление сами: установленная Lunacy Studio раз в 6 часов спрашивает GitHub, и если вышла версия новее, предлагает обновиться. Ваша задача — опубликовать выпуск. Всё остальное делает GitHub Actions.

## Коротко

1. Опишите изменения в `CHANGELOG.md` — новый раздел сверху:

   ```markdown
   ## [1.1.0] — 2026-11-02

   - Что появилось или исправлено, простыми словами
   ```

   Этот текст пользователи увидят в окне обновления.

2. Выполните:

   ```bash
   python packaging/release.py 1.1.0
   ```

   Скрипт проверит, что раздел в `CHANGELOG.md` есть, поставит версию в `studio/version.py`, сделает коммит и тег `v1.1.0` и отправит их на GitHub.

3. Через 5–10 минут на странице [Releases](https://github.com/ninezeroshine/lunacy-studio/releases) появится выпуск с установщиком, портативным ZIP и `SHA256SUMS.txt`. Ход сборки — во вкладке **Actions**.

## Номера версий

`МАЖОР.МИНОР.ПАТЧ`: исправления — `1.0.1`, новые возможности — `1.1.0`, большие переделки — `2.0.0`. Программа обновляется только на номер больше своего.

## Если сборка упала

Откройте вкладку **Actions**, запуск с красным крестиком — там видно, какой шаг сломался (обычно тесты). Исправьте, удалите тег и выпустите снова:

```bash
git tag -d v1.1.0
git push origin :refs/tags/v1.1.0
python packaging/release.py 1.1.0
```

Пока выпуск не опубликован, пользователи его не видят.

## Предварительный выпуск

Тег вида `v1.1.0-beta.1` собирается как *pre-release*: его можно скачать вручную, а автообновление его не предлагает.

## Собрать у себя

```bash
python packaging/build.py
```

Результат в `dist/`. Нужен Inno Setup 6.
